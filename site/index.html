One line — beckon Claude — bound to each machine's own modifier. Pressed once on all three: Claude comes to the front on all three.

Focus is only the first press.

Most launchers stop at "bring it to the front". beckon keeps going, and which thing happens is decided for you — there is no flag and nothing to configure.

Or let beckon hold the keys.

On macOS and Windows nothing binds hotkeys for you, so beckon can do it itself. beckon serve reads a flat TOML and reports how many of its lines actually registered.

  • macOS

    brew services start beckon is the whole install; the formula ships the LaunchAgent.

  • Windows

    beckon-serve.exe is a tray app with no console window at any point. Reload, pause, open the log, or open Settings from the tray; tick Start with Windows.

  • Linux

    Deliberately not served here. Your compositor already binds keys better than beckon could, so bindsym $mod+c exec beckon Claude is the integration.

The Windows settings window lists every binding with whether it actually registered, and writes back the same apps.toml you would edit by hand — comments and key order survive.

Windows can also fold that chord onto one key, off by default: tick the Caps Lock box in Settings and holding Caps stands in for it, so Caps+T does what Ctrl+Win+Alt+T does and your bindings do not change. It installs a low-level keyboard hook, and the three things to know before ticking it are in the README.

Ready-to-use setups, including the launchd agent and the Scheduled Task definition: examples/macos/serve/ and examples/windows/serve/.

Install.

No runtime to install, and no config file for beckon <id> — ids resolve against the OS on every call. Take whichever channel your machine already has.

Homebrew macOS · Linux

brew install xom11/tap/beckon

On macOS the formula also ships the LaunchAgent, so resident mode is one more line. Write ~/.config/beckon/apps.toml and beckon check it first.

brew services start beckon

Scoop Windows

scoop bucket add xom11 https://github.com/xom11/scoop-bucket
scoop install xom11/beckon

That also puts beckon serve in your Start menu, which launches beckon-serve.exe — a tray app with no console window at any point. First launch with no config writes a starter apps.toml and opens it in your editor.

Cargo from git

cargo install --git https://github.com/xom11/beckon

Needs Rust 1.75+ and a system C / MSVC toolchain. The binary lands in ~/.cargo/bin/beckon; add --force to update in place.

Nix flake

nix run github:xom11/beckon -- list

To pull beckon into your own flake, add inputs.beckon.url = "github:xom11/beckon" and beckon.overlays.default to your overlays; pkgs.beckon then resolves.

Every release also attaches prebuilt binaries for six targets — x86_64 and aarch64, for Linux, macOS and Windows: github.com/xom11/beckon/releases.

Questions.

Do I need a config file?

Not for beckon <id>. Ids resolve against the OS's own metadata on every call, so there is nothing to generate, no cache to rebuild and no alias file to keep in sync between machines. Only serve reads a file, and that file is a hotkey table — "ctrl+super+alt+t" = "kitty" — not a place to rename apps.

Why names instead of bundle ids?

Because canonical ids drift and names do not. Brave and Chrome mint a hash into a PWA's id when you install it, so brave-fmpnliohjhemenmnlpbfagaolkdacoja-Default is a different string on your second laptop and the dotfile you copied there silently stops working. The display name is the same on all of them. A canonical id is still accepted, and is the right answer when two apps share a display name.

Does beckon register the hotkey on Linux?

No — your compositor does, and that is a choice rather than a gap. Every Linux desktop already ships a place to bind a key to a command, and there is no single API that would cover all of them: X11 has XGrabKey, KDE has KWin scripting, Hyprland has the GlobalShortcuts portal, GNOME would need its extension, and sway has no route at all. Four implementations for one feature, on the platform that needs it least. The survey is in CLAUDE.md under Wayland hotkey.

Why does macOS ask for Accessibility?

Raising another application's window goes through the Accessibility API, and macOS gates it behind an explicit grant. The grant is bound to the binary's code signature, so building beckon yourself and rebuilding it can invalidate it and ask again. beckon doctor reports whether the process it is running in is trusted.

What does GNOME Wayland need?

The bundled shell extension from extensions/, plus a log out and back in — Wayland cannot reload the shell live. Mutter gives an external process no way to focus a window at all, so the extension runs inside gnome-shell and beckon talks to it over the session bus. KDE Wayland is the opposite case and needs nothing installed: KWin ships its own scripting engine, so beckon loads a script, reads the answer back and unloads it.

Is it fast?

The whole focus-or-launch path measured about 57 ms on the ARM64 Windows 11 laptop beckon is developed against, and about 95–105 ms on the macOS laptop it is developed against. Each figure is one machine and one run series, not a benchmark suite. The macOS figure is mostly the OS rather than beckon: open -b <bundle_id> alone accounts for 55–75 ms of it, and no API avoids that round trip. The Windows figure has no such breakdown — it started at about 443 ms and came down by changing beckon, not the OS.

Can I use Caps Lock as the modifier?

On Windows, and it is off by default. Tick the Caps Lock box in Settings and holding Caps stands in for ctrl+super+alt, so Caps+T does what ctrl+super+alt+T does — your bindings do not change, and the same file still works on a machine where the box is not ticked. The hook swallows the Caps key itself and sends the chord on as one burst, so the lock does not flip while you use it; tapping Caps on its own still toggles Caps Lock, because beckon puts that keystroke back. keyboard.caps_tap = "escape" makes the tap Esc instead, and "none" makes it do nothing. Three caveats, all real: it does nothing while an elevated window has focus, though typing the chord by hand still works there; any other remapper that already claims Caps — kanata, PowerToys Keyboard Manager, an AutoHotkey script — wins, so use one or the other and not both; and it installs a low-level keyboard hook, the same mechanism every remapper uses and the one antivirus software associates with keyloggers.
