Install.

One binary, no runtime, no config file for beckon <id>.

Homebrew macOS · Linux

brew install xom11/tap/beckon

Resident mode is one more line. macOS asks for Accessibility once.

brew services start beckon

Scoop Windows

scoop bucket add xom11 https://github.com/xom11/scoop-bucket
scoop install xom11/beckon

Puts the tray app in your Start menu. First launch writes a starter apps.toml.

Cargo from git

cargo install --git https://github.com/xom11/beckon

Needs Rust 1.75+ and a system C / MSVC toolchain.

Nix flake

nix run github:xom11/beckon -- list

Or add beckon.overlays.default to your own flake.

Questions.

Do I need a config file?

Not for beckon <id>. Ids resolve against the machine’s own metadata on every call, so there is nothing to generate and nothing to keep in sync. Only the resident mode reads a file, and that file is a hotkey table.

Why the app’s name and not its id?

Because ids drift and names do not. Chrome and Brave mint a hash into a web app’s id when you install it, so the dotfile you copied to a second laptop silently stops working. The display name is the same on all of them. A canonical id still works, and is the right answer when two apps share a name.

Why does macOS ask for Accessibility?

Raising another application’s window goes through the Accessibility API, and macOS gates it behind an explicit grant. The grant is bound to the binary’s code signature, so rebuilding beckon yourself can invalidate it. beckon doctor reports whether the process it is running in is trusted.

Does beckon map Caps Lock for me?

On Windows it can, once you turn it on — beckon holds the key itself, and Caps then stands in for the chord. The README has what turning that on costs. On macOS and Linux it does not: there Caps Lock is whatever your own remapper makes it — Karabiner, kanata, xkb — and beckon only ever sees the chord that comes out. Either way it is the chord, not the Caps key, that goes in your config.

Is it fast?

The whole focus-or-launch path measured about 57 ms on the ARM64 Windows 11 laptop beckon is developed against, and about 95–105 ms on the macOS laptop it is developed against. Each figure is one machine and one run series, not a benchmark suite — and the macOS one is mostly the OS, not beckon.
