# Scoop bucket + Homebrew tap packaging — design

Status: proposed (2026-05-25)
Owner: xom11

## Goal

Ship beckon to end users on Windows (Scoop) and macOS/Linux (Homebrew) without
asking them to install Rust + a C/MSVC toolchain. Use the existing v0.1.0
GitHub Release artifacts as the source of binaries; do not change the release
pipeline. Make subsequent releases (v0.1.1, v0.2.0, …) update both package
managers automatically with zero manual steps.

## Non-goals

- winget submission. SmartScreen reputation hurdles + manifest review make it
  not worth the cost until beckon has visible install traction.
- homebrew-core (the central Homebrew repo). Requires popularity / notability
  threshold beckon does not yet meet; a per-user tap is the standard ramp-up.
- AUR / Linux distro packages. Out of scope for this iteration.
- Rebuilding or re-tagging v0.1.0. Existing release stays as-is.
- crates.io publication. Independent concern; tracked separately if desired.

## Constraints

- Homebrew tap repo name MUST follow `homebrew-<TAP>` so that
  `brew tap xom11/<TAP>` resolves. The existing `xom11/beckon` repo cannot be
  reused as the tap — renaming it would break Cargo / Nix / Hammerspoon
  consumers that reference `github.com/xom11/beckon`.
- Scoop bucket has no naming constraint (any repo with `bucket/*.json` works),
  but for parity with Homebrew we use a dedicated multi-app catalog repo.
- Both catalog repos must be **public** for `brew tap` / `scoop bucket add`
  to fetch them.

## Architecture

Three repos, one source of truth (`xom11/beckon`), two thin catalog repos
auto-updated by CI.

```
xom11/beckon                         (source + binaries + templates)
├── crates/...                       — Rust source (unchanged)
├── packaging/
│   ├── homebrew/beckon.rb.template  — Homebrew Formula template
│   └── scoop/beckon.json.template   — Scoop manifest template
├── .github/workflows/
│   ├── ci.yml                       (unchanged)
│   ├── release.yml                  (unchanged; builds 6 binaries on `v*` tag)
│   └── bump-packagers.yml           NEW: renders templates, pushes to catalogs
├── README.md                        — Installation section added
└── CLAUDE.md                        — Distribution section updated

xom11/homebrew-tap                   NEW, public, multi-app catalog
└── Formula/beckon.rb                — autogenerated, never hand-edited
                                       (future: Formula/<other-tool>.rb)

xom11/scoop-bucket                   NEW, public, multi-app catalog
└── bucket/beckon.json               — autogenerated, never hand-edited
                                       (future: bucket/<other-tool>.json)
```

**Multi-app catalog naming** (vs per-tool `homebrew-beckon`) is chosen so
future xom11 tools reuse the same two repos. Users add the tap / bucket
once, ever.

### Why templates live in `xom11/beckon`

- PRs that change manifest shape (e.g. add a `depends_on`, change install
  layout) are reviewable against source in the same diff that motivated them.
- The Homebrew Formula was previously written this way in commit `5324019`
  (later reverted as "deferred"); resurrecting that location is the cheapest
  thing that works.
- The catalog repos themselves never receive hand-edits, only CI-rendered
  outputs. Their git history is the audit log of "what users actually saw".

## Manifest contents

### Homebrew Formula (`packaging/homebrew/beckon.rb.template`)

```ruby
class Beckon < Formula
  desc "Cross-platform focus-or-launch app switcher"
  homepage "https://github.com/xom11/beckon"
  version "{{VERSION}}"
  license any_of: ["Apache-2.0", "MIT"]

  on_macos do
    on_arm do
      url "https://github.com/xom11/beckon/releases/download/v#{version}/beckon-#{version}-aarch64-apple-darwin.tar.gz"
      sha256 "{{SHA256_DARWIN_ARM}}"
    end
    on_intel do
      url "https://github.com/xom11/beckon/releases/download/v#{version}/beckon-#{version}-x86_64-apple-darwin.tar.gz"
      sha256 "{{SHA256_DARWIN_X86}}"
    end
  end

  on_linux do
    on_arm do
      url "https://github.com/xom11/beckon/releases/download/v#{version}/beckon-#{version}-aarch64-unknown-linux-gnu.tar.gz"
      sha256 "{{SHA256_LINUX_ARM}}"
    end
    on_intel do
      url "https://github.com/xom11/beckon/releases/download/v#{version}/beckon-#{version}-x86_64-unknown-linux-gnu.tar.gz"
      sha256 "{{SHA256_LINUX_X86}}"
    end
  end

  def install
    bin.install "beckon"
  end

  test do
    assert_match version.to_s, shell_output("#{bin}/beckon --version")
  end
end
```

Differences from the reverted `5324019` Formula: adds `on_intel` blocks for
both macOS and Linux so all 4 prebuilt Unix binaries are wired up (the
original only covered `on_arm` for both OSes).

### Scoop manifest (`packaging/scoop/beckon.json.template`)

```json
{
  "version": "{{VERSION}}",
  "description": "Cross-platform focus-or-launch app switcher",
  "homepage": "https://github.com/xom11/beckon",
  "license": "Apache-2.0 OR MIT",
  "architecture": {
    "64bit": {
      "url": "https://github.com/xom11/beckon/releases/download/v{{VERSION}}/beckon-{{VERSION}}-x86_64-pc-windows-msvc.zip",
      "hash": "{{SHA256_WIN_X86}}"
    },
    "arm64": {
      "url": "https://github.com/xom11/beckon/releases/download/v{{VERSION}}/beckon-{{VERSION}}-aarch64-pc-windows-msvc.zip",
      "hash": "{{SHA256_WIN_ARM}}"
    }
  },
  "bin": "beckon.exe",
  "checkver": "github",
  "autoupdate": {
    "architecture": {
      "64bit": {
        "url": "https://github.com/xom11/beckon/releases/download/v$version/beckon-$version-x86_64-pc-windows-msvc.zip"
      },
      "arm64": {
        "url": "https://github.com/xom11/beckon/releases/download/v$version/beckon-$version-aarch64-pc-windows-msvc.zip"
      }
    },
    "hash": {
      "url": "$url.sha256"
    }
  }
}
```

`checkver: github` + `autoupdate` lets community contributors run
`scoop checkver beckon` against this manifest to detect new beckon releases
even if our CI push is delayed.

## CI workflow

New file: `.github/workflows/bump-packagers.yml`.

```yaml
name: Bump packagers
on:
  release:
    types: [published]
  workflow_dispatch:
    inputs:
      tag:
        description: 'Existing release tag to backfill (e.g. v0.1.0)'
        required: true
        type: string

permissions:
  contents: read

jobs:
  bump:
    runs-on: ubuntu-latest
    env:
      TAG:   ${{ inputs.tag || github.event.release.tag_name }}
      GH_TOKEN: ${{ secrets.PACKAGER_TOKEN }}
    steps:
      - uses: actions/checkout@v6

      - name: Resolve version + fetch sha256 files
        id: hashes
        run: |
          set -euo pipefail
          version="${TAG#v}"
          echo "version=${version}" >> "$GITHUB_OUTPUT"
          mkdir -p _hashes
          for tgt in \
            aarch64-apple-darwin \
            x86_64-apple-darwin \
            aarch64-unknown-linux-gnu \
            x86_64-unknown-linux-gnu \
            aarch64-pc-windows-msvc \
            x86_64-pc-windows-msvc
          do
            ext=tar.gz
            case "$tgt" in *windows*) ext=zip ;; esac
            asset="beckon-${version}-${tgt}.${ext}.sha256"
            gh release download "${TAG}" -R xom11/beckon -p "$asset" -D _hashes
            hash="$(awk '{print $1}' "_hashes/${asset}")"
            key="$(echo "$tgt" | tr 'a-z-' 'A-Z_')"
            echo "SHA_${key}=${hash}" >> "$GITHUB_OUTPUT"
          done

      - name: Render Formula
        run: |
          set -euo pipefail
          v='${{ steps.hashes.outputs.version }}'
          sed \
            -e "s|{{VERSION}}|${v}|g" \
            -e "s|{{SHA256_DARWIN_ARM}}|${{ steps.hashes.outputs.SHA_AARCH64_APPLE_DARWIN }}|g" \
            -e "s|{{SHA256_DARWIN_X86}}|${{ steps.hashes.outputs.SHA_X86_64_APPLE_DARWIN }}|g" \
            -e "s|{{SHA256_LINUX_ARM}}|${{ steps.hashes.outputs.SHA_AARCH64_UNKNOWN_LINUX_GNU }}|g" \
            -e "s|{{SHA256_LINUX_X86}}|${{ steps.hashes.outputs.SHA_X86_64_UNKNOWN_LINUX_GNU }}|g" \
            packaging/homebrew/beckon.rb.template > beckon.rb

      - name: Render Scoop manifest
        run: |
          set -euo pipefail
          v='${{ steps.hashes.outputs.version }}'
          sed \
            -e "s|{{VERSION}}|${v}|g" \
            -e "s|{{SHA256_WIN_X86}}|${{ steps.hashes.outputs.SHA_X86_64_PC_WINDOWS_MSVC }}|g" \
            -e "s|{{SHA256_WIN_ARM}}|${{ steps.hashes.outputs.SHA_AARCH64_PC_WINDOWS_MSVC }}|g" \
            packaging/scoop/beckon.json.template > beckon.json

      - name: Push Formula to homebrew-tap
        run: |
          set -euo pipefail
          v='${{ steps.hashes.outputs.version }}'
          tmp="$(mktemp -d)"
          git clone "https://x-access-token:${GH_TOKEN}@github.com/xom11/homebrew-tap.git" "$tmp"
          mkdir -p "$tmp/Formula"
          mv beckon.rb "$tmp/Formula/beckon.rb"
          cd "$tmp"
          git config user.name  'beckon-release-bot'
          git config user.email 'beckon-release-bot@users.noreply.github.com'
          git add Formula/beckon.rb
          git diff --staged --quiet && exit 0
          git commit -m "beckon ${v}"
          git push

      - name: Push manifest to scoop-bucket
        run: |
          set -euo pipefail
          v='${{ steps.hashes.outputs.version }}'
          tmp="$(mktemp -d)"
          git clone "https://x-access-token:${GH_TOKEN}@github.com/xom11/scoop-bucket.git" "$tmp"
          mkdir -p "$tmp/bucket"
          mv beckon.json "$tmp/bucket/beckon.json"
          cd "$tmp"
          git config user.name  'beckon-release-bot'
          git config user.email 'beckon-release-bot@users.noreply.github.com'
          git add bucket/beckon.json
          git diff --staged --quiet && exit 0
          git commit -m "beckon ${v}"
          git push
```

### Idempotency

Each step exits cleanly if there is no diff (`git diff --staged --quiet`). Re-
running the workflow for the same tag is a no-op.

### Secret

`PACKAGER_TOKEN` — a fine-grained GitHub PAT created by the repo owner. Scope:
**Contents: Read & Write** on `xom11/homebrew-tap` and `xom11/scoop-bucket`
only. No access to `xom11/beckon` or any other repo. Default expiry 90 days
is acceptable; renewal procedure documented in README of `homebrew-tap`.

Why PAT and not `GITHUB_TOKEN`: the default workflow token is scoped to the
running repo only — it cannot push to a sibling repo.

Alternative considered: a GitHub App installed on all 3 repos. Cleaner
permissions model but adds bootstrapping cost. Defer until / unless PAT
renewal becomes a real friction point.

## Bootstrap (one-time)

Ordered. Each step is blocked by the previous one.

| # | Step | Who | How |
|---|------|-----|------|
| 1 | Create catalog repos | claude | `gh repo create xom11/homebrew-tap --public --description "Homebrew tap for xom11 tools"` and same for `scoop-bucket` |
| 2 | Seed each catalog with minimal README + LICENSE | claude | `gh repo clone`, write README, commit, push |
| 3 | Add source-side changes (templates + workflow + README + CLAUDE.md) to `xom11/beckon` | claude | Branch → commit → fast-forward merge to `main` per standing authorization, then push |
| 4 | Create PAT `PACKAGER_TOKEN` | **user** | github.com/settings/personal-access-tokens → fine-grained → repos `homebrew-tap` + `scoop-bucket` selected → Contents: write |
| 5 | Add secret to `xom11/beckon` | **user** | `gh secret set PACKAGER_TOKEN -R xom11/beckon` (paste token when prompted) |
| 6 | Backfill v0.1.0 | claude | `gh workflow run bump-packagers.yml -R xom11/beckon -f tag=v0.1.0` |
| 7 | Verify Homebrew | user (macOS) | `brew tap xom11/tap && brew install beckon && beckon --version` |
| 8 | Verify Scoop | user (Windows) | `scoop bucket add xom11 https://github.com/xom11/scoop-bucket && scoop install xom11/beckon && beckon --version` |

Steps 1–3 are independent and could be parallelized, but step 6 requires
all three plus steps 4–5 to have succeeded.

## Verification + rollback

**On bump**: workflow logs show the rendered Formula + manifest diff before
push. Catalog repos retain full git history — `git revert` on the catalog
restores the previous manifest in seconds. Users running `brew upgrade` or
`scoop update` next pick up the revert.

**Manual smoke test** for each release: claude runs `gh workflow run` if the
auto-trigger somehow misfires; user runs `brew/scoop upgrade beckon` on at
least one host of each OS family.

## Open questions

None blocking. Considered and deferred:

- **Automatic test of installed binary in CI**: would need macOS + Windows
  runners running `brew install` / `scoop install` against the live catalog
  after push. Adds 2–3 minutes of CI per release. Defer until a botched
  release actually happens.
- **Bottle signing / notarization** on macOS: not required for Homebrew tap
  installs (tarball, no .app). Revisit if we ever ship a `.app` bundle.
- **Multiple-tool support in the same release flow**: workflow is currently
  beckon-specific (hardcoded template paths, output filenames). When a
  second xom11 tool needs the same treatment, parametrize at that point —
  do not over-engineer now.

## Future considerations

- **winget**: once beckon has install signal (e.g. 100+ scoop downloads), the
  SmartScreen reputation problem softens; revisit winget submission then.
- **homebrew-core**: tap → core is a graduation path once notability criteria
  (~75 stars, sustained maintenance) are met.
- **Cargo / crates.io**: orthogonal to this work; can be added without
  affecting tap or bucket.
