# A landing page for beckon, on GitHub Pages

Status: design approved 2026-08-12. Not built.

## Goal

A single static page at `xom11.github.io/beckon` that answers, in the first
screenful, what beckon is and why it is not the thing the reader already has.
The shape is borrowed from [homerow.app](https://homerow.app/) — sticky nav,
one enormous headline, an in-page keyboard affordance, feature blocks carried
by motion, a compatibility grid, an FAQ. The content is beckon's own.

The one claim the page leads with is **cross-platform**, because it is the
only one no competitor can answer. Homerow is macOS. skhd is macOS. AHK is
Windows. `beckon Claude` is the same line on all three.

## Why now

`v0.8.0` ships all four Linux backends, macOS, Windows, resident mode, a
settings window and two packager channels. The repo has 0 stars and
`homepageUrl` is empty. Everything a reader needs is in a 400-line README that
opens with a `cargo install` line — which is a document for someone already
persuaded.

## Non-goals

- **A docs site.** README stays the documentation. The page links to it.
- **Testimonials.** Homerow's *"Loved by keyboard enthusiasts"* block is
  dropped and not replaced. The repo has no users to quote yet, and writing
  the block anyway means fabricating reviews. Revisit when real issues and
  stars exist.
- **Pricing.** Replaced by Install.
- **Analytics**, external fonts, a JS framework, a build step, `node_modules`.
- **Benchmark numbers in the hero.** 57 ms (Windows) and ~95 ms (macOS) are
  each one machine, one run series. They belong in the FAQ, carrying the
  machine they were measured on — never on the hero as a bare figure.

## Constraints

1. **It must still work after being ignored for a year.** No dependency that
   can rot, no lockfile, no toolchain — three text files plus two PNGs derived
   from the icon, all of which a browser opens from `file://`.
2. **Every claim traces to the repo.** Environment grid ← `examples/` plus the
   dispatch table in `CLAUDE.md`; letter→app table ← README; install commands
   ← README; version ← `Cargo.toml`. Nothing invented for copy's sake.
3. **The page is the motion.** With no screenshots and no video, the demos are
   synthetic — which makes `prefers-reduced-motion` load-bearing, not a
   courtesy.
4. **Not `docs/`.** That directory holds `superpowers/specs`, `plans` and
   `measurements` — internal working notes. Serving Pages from `/docs` renders
   all of it as an indexable website.

## Architecture

### 1. Layout

```
site/
├── index.html        # the whole page
├── beckon.css        # tokens, components, sections, motion
├── beckon.js         # ~60 lines vanilla: accordion, copy, OS tabs, theme
├── favicon.png       # sips -s format png -Z 64  assets/beckon.ico
└── icon-512.png      # sips -s format png -Z 512 assets/beckon.ico
```

`assets/beckon.ico` stays the single source of the mark; the two PNGs are
derived from it and regenerated by the same two commands if it ever changes.

### 2. Deploy

`.github/workflows/pages.yml`, Pages source = **GitHub Actions**:

```yaml
name: Pages
on:
  push:
    branches: [main]
    paths: ['site/**', '.github/workflows/pages.yml']
  workflow_dispatch:
permissions: { contents: read, pages: write, id-token: write }
concurrency: { group: pages, cancel-in-progress: false }
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: { name: github-pages, url: "${{ steps.deploy.outputs.page_url }}" }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with: { path: site }
      - id: deploy
        uses: actions/deploy-pages@v4
```

The `paths:` filter keeps a Rust-only commit from redeploying. `workflow_dispatch`
is there because this repo has already been bitten once by a workflow that
never fired on its own (see *Distribution* in `CLAUDE.md`) — a manual handle
costs one line.

**One manual step, and it fails silently without it:** repo Settings → Pages →
Source must be set to *GitHub Actions*. Left at *Deploy from a branch*, the
workflow goes green and publishes nothing.

### 3. Tokens

Accent is **`#2563EB`**, read out of `assets/beckon.ico` rather than chosen:
converted to PNG, IDAT decompressed, background pixel is colortype 6,
`RGB(37, 99, 235)`. The mark is a white lowercase `b` on that blue.

Dark is the default look, as on homerow, but the page is theme-aware. The full
light palette is defined on bare `:root`; only the tokens that differ are
redefined under `@media (prefers-color-scheme: dark)` and again under
`:root[data-theme="dark"]` so the toggle wins both ways. `body` gets an
explicit background token — never transparent.

| Token | Light | Dark |
|---|---|---|
| `--bg` | `#FFFFFF` | `#0B0D12` |
| `--bg-raised` | `#F6F7F9` | `#141822` |
| `--fg` | `#0B0D12` | `#E8EAF0` |
| `--fg-dim` | `#5A6072` | `#9AA1B4` |
| `--rule` | `#E3E6EC` | `#232936` |
| `--accent` | `#2563EB` | `#5B8CFF` |

Dark lifts the accent to `#5B8CFF`. Computed, not eyeballed: `#2563EB` on
`#0B0D12` is **3.8:1**, which fails WCAG AA for body text; `#5B8CFF` on the
same ground is **6.1:1** and passes. The light accent stays `#2563EB` — 5.2:1
on white.

Type is the system stack — `ui-sans-serif, -apple-system, "Segoe UI", Roboto,
…` for prose, `ui-monospace, SFMono-Regular, "Cascadia Mono", Consolas, …` for
keycaps and code. No webfont: no external request, no FOUT, no third party
learning who reads the page. Hero is `clamp(2.75rem, 7vw, 5.5rem)` with
`letter-spacing: -0.03em`.

### 4. The keycap, and why it is one component

`.key` is a single CSS component — monospace, `--bg-raised` face, 1px `--rule`
border, a 2px bottom shadow that shortens by 1px under `.key[data-down]` so the
cap visibly depresses.

It is reused verbatim in four places: the hero chord, the algorithm demo, the
letter→app table in *Works with your setup*, and the Caps Lock line in
*Or let beckon hold the keys*. That reuse is what makes the page read as one
system rather than eight unrelated blocks, and it is cheaper than styling four
things that nearly match.

### 5. Motion

Two demos, both pure CSS `@keyframes` on a fixed timeline, no JS, no
`Intersection Observer`:

- **Hero** — the chord `[Ctrl][Win][Alt]+[C]` depresses; three window chromes
  labelled macOS / Windows / Linux each raise a `Claude` window at the same
  beat. The point is simultaneity: one line, three OSes.
- **Algorithm** — the same chord pressed five times against a fixed window
  set, stepping `focus → cycle 2/3 → cycle 3/3 → back to Brave → hidden`,
  captioned with the step number from the focus algorithm.

Under `@media (prefers-reduced-motion: reduce)` both animations are set to
`animation: none` and each demo's markup carries the *final* state as its
static appearance, with the intermediate steps listed as text. A reader who
turns motion off must not lose the argument, and on this page the animation
*is* the argument.

### 6. Sections

| # | Section | Substance |
|---|---|---|
| 0 | Nav (sticky) | `b` mark · Install · How it works · Docs → README · GitHub · theme toggle |
| 1 | Hero | *One key per app. Every OS you use.* Sub: the same `beckon Claude` on macOS, Windows, Linux. Chord demo. Two buttons: Install, GitHub. |
| 2 | Focus is only the first press | The five-step algorithm as prose + the repeat-press demo. This is what separates beckon from a launcher. |
| 3 | Type the name, not the id | `beckon Claude` beside `brave-fmpnliohjhemenmnlpbfagaolkdacoja-Default`, and the reason: Brave/Chrome PWA hashes are minted at install time and differ per machine, so canonical ids cannot be synced through a dotfile. `Name=` can. |
| 4 | Works with your setup | Eight tiles (below) + the letter→app table + the per-OS modifier defaults. |
| 5 | Or let beckon hold the keys | `serve` on macOS and Windows: flat TOML, `brew services start beckon`, the Windows tray app and its settings window. States plainly that Linux is not served here and the compositor binds the key. |
| 6 | Install | Four tabs — Homebrew, Scoop, Cargo, Nix — each a copyable block. Defaults to the visitor's platform via `navigator.platform`, falls back to Homebrew. |
| 7 | FAQ | `<details>`/`<summary>`, seven entries (below). |
| 8 | Footer | MIT OR Apache-2.0 · v0.8.0 · repo · releases. |

**Section 4's eight tiles**, each with its status and the one thing that
surprises people:

| Tile | Note it must carry |
|---|---|
| macOS | needs Accessibility permission |
| Windows | Start Menu + MSIX/AppX resolution |
| sway | — |
| i3 | — |
| Hyprland | — |
| GNOME (Wayland) | **requires the bundled shell extension** |
| KDE (Wayland) | nothing to install — rides KWin scripting |
| XFCE · openbox · awesome · fluxbox | any EWMH X11 desktop |

The GNOME note is not optional. Every other tile works from a package install;
that one needs a shell extension and a re-login, and a grid that hides it is
selling something beckon does not do.

**FAQ, all seven answerable from the repo:**

1. Do I need a config file? — Not for `beckon <id>`. Only `serve` reads one.
2. Why names instead of bundle ids? — PWA hash drift.
3. Does beckon register the hotkey on Linux? — No, the compositor does, and
   that is a choice; links to the *Wayland hotkey* survey.
4. Why does macOS ask for Accessibility? — and the note that the grant is
   bound to the signed binary.
5. What does GNOME Wayland need? — the extension, and why Mutter forces it.
6. Is it fast? — the measured figures, each stated with the machine and
   command it came from. Never as a bare number.
7. Can I use Caps Lock as the modifier? — Windows, opt-in, and the three
   caveats already in the README (UIPI, other remappers, EDR).

### 7. JavaScript

Roughly sixty lines, no framework, all progressive enhancement — every section
is readable and every link works with JS disabled:

- FAQ is native `<details>`; JS only closes siblings on open.
- Copy button on each install block via `navigator.clipboard`, hidden when the
  API is absent.
- OS tabs: the HTML ships all four panels **visible**, each under its own
  heading, and JS adds `hidden` to three of them on load. Written the other way
  round — `hidden` in the markup, removed by JS — a reader without JS sees
  three empty gaps and no way to install on their OS.
- Theme toggle: writes `data-theme` on `<html>` plus `localStorage`; absent, CSS
  still follows `prefers-color-scheme`.

## Data flow

None. There is no server, no form, no fetch, no third-party embed. The page
makes zero network requests after its own three files and two PNGs.

## Error handling

The failure modes are a static page's, and each has a structural answer rather
than a runtime one:

- **Pages source misconfigured** → workflow green, site 404. Caught by opening
  the deployment URL once after the first run; called out in §2 because it is
  invisible otherwise.
- **A link to the repo goes stale** (a renamed `examples/` path) → the link
  check in Testing.
- **A colour defined only inside a media query** → renders unstyled for one of
  the three theme states. Caught by the token audit in Testing.
- **An external asset sneaks in** → grep in Testing.

## Testing

Verifiable without a browser:

1. **No external requests.** `grep -nE '(src|href)="https?://' site/*.html` must
   return only `<a>` tags; `grep -n 'url(http' site/*.css` must return nothing.
2. **Token audit.** Every `--*` custom property read anywhere must be defined
   on bare `:root`, not only inside `@media` or `[data-theme]`.
3. **Link check.** Every in-page `href="#…"` has a matching `id`; every
   `github.com/xom11/beckon/...` path exists on disk.
4. **Reduced motion.** Every element with an `animation` appears under the
   `prefers-reduced-motion: reduce` block.
5. **Claim check.** Install commands byte-match the README; the letter→app
   table matches; the version matches `Cargo.toml`.

Needing a browser — `python3 -m http.server` from `site/`, driven with the
`browse` skill:

6. Renders in both themes and at 375 px, 768 px and 1440 px with no horizontal
   scroll on `body`.
7. Tab order reaches nav, both hero buttons, the OS tabs, every FAQ summary and
   the footer links, with a visible focus ring on each.
8. Both demos complete a full cycle and loop cleanly.

## Documentation

- README gains the site link near the top.
- Repo `homepageUrl` set to the Pages URL (currently empty).
- `CLAUDE.md` gains a short *Landing page* entry under Distribution: where the
  site lives, why it is `site/` and not `docs/`, and the manual Pages-source
  step.

## Deferred

- **An Open Graph card.** v1 points `og:image` at `icon-512.png`, which
  previews as a square mark rather than a designed card. A proper 1200×630
  wants either a rasterizer in CI or a checked-in PNG; neither is worth
  blocking the page on.
- **Real screenshots and video.** The synthetic demos are illustrations, and
  the page should say so implicitly by never captioning them as recordings.
  When `airm3` and `a14` can produce clips, §5's markup is meant to be swapped
  for `<video>` at the same dimensions without touching layout.
- **Testimonials**, per Non-goals, when there are real ones.
